# خطة إكمال لعبة C++ Android

هذا الملف يثبت حالة المشروع والخطوات التالية المطلوبة لمتابعة العمل بعد
فتح المشروع من `replit.com` أو بعد انتهاء جلسة العمل الحالية.

## الحالة الحالية

- المشروع لعبة native بلغة C++ باستخدام raylib، وليس موقع ويب.
- النسخة الحالية تعرض نموذجًا تجريبيًا: لاعب مكعب، أرضية، ومبانٍ مكعبة.
- أزرار الحركة على الشاشة موجودة وتقرأ اللمس.
- يوجد مشروع Android داخل `cpp-game/android`.
- تم إنشاء APK تجريبي بمعمارية `arm64-v8a`.
- ملف APK الحالي لا يحتوي على أصول المدينة أو نموذج الشخصية؛ لذلك حجمه صغير.
- ملف المدينة موجود في `attached_assets` داخل أرشيفات ZIP بصيغة FBX.
- مكتبة الأنيميشن تحتوي على نماذج GLB وFBX، ومنها:
  `Mannequin_F.glb` و `UAL2_Standard.glb`.

## الخطوة التالية المباشرة

بعد فحص المشروع من المتصفح، يجب تنفيذ العمل داخل `cpp-game` بهذا الترتيب:

1. فحص ملفات المدينة واختيار مجموعة صغيرة مناسبة للنسخة الأولى.
2. تحويل ملفات المدينة من FBX إلى GLB أو GLTF؛ raylib لا يحمّل FBX
   مباشرة بالطريقة المستخدمة حاليًا.
3. استخراج نموذج الشخصية بصيغة GLB والأنيميشن المطلوب.
4. وضع الأصول المختارة داخل:

   ```text
   cpp-game/android/app/src/main/assets/
   ```

5. إضافة كود C++ لتحميل الأصول باستخدام `LoadModel` و
   `LoadModelAnimations` مع التحقق من فشل التحميل.
6. ضبط مقياس المدينة والشخصية واللاعب بحيث يكون اللاعب بالحجم الصحيح
   مقارنة بالأبواب والطرق والمباني.

## نظام تحميل المدينة التدريجي

لا يجب تحميل المدينة كاملة عند تشغيل اللعبة. سيتم تقسيم العالم إلى مربعات
أو **Chunks**، مثلًا:

```text
world/
  chunk_-1_-1.glb
  chunk_0_-1.glb
  chunk_1_-1.glb
  chunk_-1_0.glb
  chunk_0_0.glb
  chunk_1_0.glb
```

سيعمل مدير العالم بهذه القواعد:

- حساب رقم المربع من موقع اللاعب.
- إبقاء مربع اللاعب والمربعات المجاورة فقط في الذاكرة.
- تحميل المربع الجديد عند اقتراب اللاعب من حدوده.
- إزالة المربع البعيد بعد ابتعاد اللاعب عنه.
- عدم تنفيذ تحميل أو حذف عدة ملفات ضخمة في الإطار نفسه.
- عرض حالة تحميل بسيطة بدل تجميد اللعبة.
- الاحتفاظ بحد أقصى لعدد المربعات المحملة لتناسب الهاتف.

الهدف هو منع تجمّد التطبيق أو ظهور رسالة **التطبيق لا يستجيب** بسبب تحميل
المدينة كاملة دفعة واحدة.

## التصادم

سيتم فصل التصادم عن نموذج العرض قدر الإمكان:

- كل مبنى أو مجموعة مبانٍ لها `BoundingBox` مبسط.
- اللاعب يستخدم صندوق تصادم صغير مناسب لحجمه.
- لا يتم استخدام شبكة المدينة التفصيلية للتصادم في النسخة الأولى.
- يتم اختبار الحركة قبل تطبيقها لمنع مرور اللاعب داخل المباني.

## حماية أداء الهاتف

- تحميل الأصول عند الحاجة فقط.
- عدم تحميل ملفات FBX أو ZIP مباشرة أثناء اللعب.
- استخدام GLB/GLTF صغيرة ومقسمة بدل نموذج مدينة واحد ضخم.
- تقليل الخامات غير المستخدمة.
- تحرير النماذج والأنيميشن عند إزالة الـChunk.
- اختبار الذاكرة ومعدل الإطارات على هاتف قريب من Realme C53.
- إبقاء النسخة الأولى على `arm64-v8a` وAndroid 10 أو أحدث.

## إعادة بناء APK

بعد اكتمال التعديلات وفتح المشروع من `replit.com`، يتم تشغيل:

```bash
cd cpp-game
bash build_android.sh
```

ثم التحقق من الملف:

```text
cpp-game/android/app/build/outputs/apk/debug/app-debug.apk
```

ويجب تجربة APK على الهاتف قبل رفعه إلى GitHub. عند نجاح الاختبار، يرفع ملف
APK إلى GitHub مع `git add -f` لأنه ملف ناتج عن البناء ومستبعد عادةً من
`.gitignore`.

## معيار اكتمال المرحلة

تُعتبر هذه المرحلة مكتملة عندما:

- تظهر المدينة الحقيقية بدل المباني المكعبة التجريبية.
- يتحرك اللاعب بحجم منطقي داخل الشوارع.
- تعمل أزرار اللمس.
- لا يتم تحميل العالم كاملًا عند بدء اللعبة.
- يتم تحميل وإزالة الـChunks أثناء الاستكشاف دون تجمّد واضح.
- تعمل التصادمات الأساسية مع المباني.
- يبدأ APK على الهاتف ويظل مستجيبًا.
- يتم رفع APK النهائي إلى مستودع GitHub.
